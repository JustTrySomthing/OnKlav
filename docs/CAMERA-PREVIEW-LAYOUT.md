# Camera preview and floating controls

The portrait SDK header now owns Flash, Capture timer and Settings on its right side. Timer Off is a dedicated crossed-out timer vector, with accessible Off state rather than a visible word. Three- and ten-second states show a compact numeric badge and retain the existing timer cycle. The capture area no longer reserves separate toolbar, zoom, mode and shutter rows. Zoom, Photo/Video, captures, shutter and camera switch are overlaid on a graduated dark scrim within the preview stage. Portrait still respects the Android navigation-bar safe area.

Landscape capture uses the existing immersive-media lifecycle to hide app chrome and Android system bars, restore them when leaving capture, and keep the display awake. The floating top controls include Back and the same flash/timer/settings actions. The bottom row starts with horizontal zoom at the left, followed by captures, mode selection, shutter and lens switch (or recording pause/resume). Display cutouts and system gesture insets are respected. Gallery restores normal app chrome; startup/access errors do not strand the user in a headerless screen. Native CameraX capture, recording, flash, focus, viewport, rotation, shutter sound and pending-capture recovery are retained.

The chosen output ratio remains accurate. The actual camera preview fits the larger stage without stretching or showing an arbitrary cropped window; ratios that differ from the screen still have letterboxing. Controls float over the stage rather than shrinking it. This preserves the prior requirement that the preview correspond to the image being captured.

Source update after 0.100.18-rc1. This task does not request a new APK. Validation and restoration diagnostics are retained in `docs/evidence/camera-layout/` and `docs/camera-layout-verification.json`. Physical-phone sensor/FOV, cutout/gesture behavior, recording rotation and capture/provider performance remain device acceptance work.
