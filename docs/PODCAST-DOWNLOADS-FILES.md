# Podcasts downloads and Files actions — 0.84

Podcasts uses the same signed SDK app and host broker as other included apps. Each episode in a show or Recent has a Download action before Play. Its icon changes to the shared rotating Read Aloud activity arrow during the request, then X after a complete download. X deletes only that download; subscriptions and recent history remain. Playing a completed download bypasses feed fetching and remote stream resolution. Playback positions use the same episode key for streaming and local playback. Deleting the currently playing download stops its player and releases its file handle.

Downloads stream directly to private disk, support episodes over20MB (2GiB maximum), validate public HTTPS addresses at every redirect, check live podcast/storage grants during transfers and discard incomplete staging files. A completed audio file and metadata are committed before being listed. Saved files are scoped by app ID and publisher, survive app closure and updates, and are not held in memory. Requests are foreground operations; leaving the app or Cancel interrupts an unfinished request. There is no promise of background continuation. Up to500 completed downloads are supported; the device must have sufficient space. Providers can still remove or restrict their audio.

Files has a folder-plus action inside the right side of Search. A folder created from Files Home is placed in Documents and shown there after Save. Every row has a pencil action, including folders. Personal file/folder menus offer Copy, Paste, Delete, Rename, Move, Show Properties, Share and Compress. Copy puts an opaque selection on the app's clipboard; Paste Here and a folder's Paste action copy it into the destination. Move retains the existing destination chooser. System/built-in roots and Trash have their appropriate protected or restore menus.

Canonical Rust content operations implement recursive copies, note-to-text copying, ZIP creation, folder ZIP sharing and metadata. Copies have independent IDs/bytes. ZIPs preserve nested paths and originals. Failed native copy/compression removes newly staged output. Copy/compress operate on up to256MiB and the bounded content index; folder cycles, symlinks and protected mutations are rejected. ZIP sharing stages a read-only content URI for Android's share chooser. Sharing grants access only to that staged copy.

Connected Android folders retain the existing per-app, explicitly chosen document-tree permissions. Their menus also expose properties/share/compress and provider move/copy. Copy falls back to bounded document streaming when copyDocument is unsupported. Sharing folders creates ZIPs; compression writes a ZIP to the source parent (inside a connected root when that root is selected). Source trees remain untouched by copy/compression. Cross-storage paste is intentionally rejected with Import/Save a Copy guidance, and provider-specific inability to move/write is reported. No broad storage permission is added.

Validation details are in downloads-files-verification.json. Host/native checks are separate from physical-phone audio, provider and touch acceptance.
