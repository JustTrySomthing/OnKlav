# Email everyday workflow and UI refinement

Inbox rows now use consistent themed cards with clearer unread, attachment, account and conversation-count indicators. Message links from Message-ID, References and In-Reply-To build account-isolated conversations; subject alone never links unrelated messages. A reader conversation navigator exposes the downloaded messages individually, with folder/date context. Settings retains an individual-message mode. Search/unread filters and bulk selection apply to the matching downloaded members; thread-level selection selects those displayed members. Header JSON remains backward-compatible; old headers gain references as their pages refresh.

To/Cc/Bcc offer inline, deduplicated recent-correspondent suggestions for the selected sending account, including local drafts. Suggestions are debounced and searched off the UI thread; correspondent history is capped to the most recent 1,500 headers. Quoted display-name commas and existing recipients are preserved. This adds no phone address-book access or permission. Empty/invalid To disables Send. The composer uses a labeled Send control, compact large-text/small-screen navigation, persistent formatting controls outside the scrolling address/body form, a responsive body height and explicit saving/saved state. Account onboarding keeps advanced server settings and preferences collapsed; connection edits cannot accidentally use Save preferences. Existing provider registration requirements remain visible.

Background head refresh now retains older downloaded inbox pages while dropping stale UIDVALIDITY data. The existing periodic job is not rescheduled on every UI/busy change. Pagination stops if the server makes no UID progress. Search/account/tab changes cannot redirect an in-flight mailbox request. Normal Android Back saves a draft or returns from the reader, and cancels an active operation before leaving it.

Draft flushing continues in the app’s IO scope after the view model leaves, under the same operation mutex and live permission check. A stale draft snapshot cannot overwrite a sending/sent/uncertain phase or a newer saved revision. Sending also verifies the saved draft phase/revision immediately before transport. No SMTP auto-retry was added. Permissions remain revocable, cached content/attachments encrypted, TLS checks strict, links explicit and unknown delivery outcomes protected.

Verification: email-polish-verification.json and evidence/email-polish. Native and SDK package inputs did not change; no new dependency or APK. Host/UI/loopback tests do not establish real-account, physical-phone/background/battery or independent security acceptance. Provider configuration and those external qualification gates remain as described in EMAIL.md. This is periodic mail checking, not instant push, provider draft synchronization, scheduled sending, POP/EWS/ActiveSync or native Proton integration.
