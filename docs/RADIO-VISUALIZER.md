# Radio music visualizer

Current refinement adds7styles, a snapping wheel/six color swatches, orientation-fitted geometry and live-station continuity. See [RADIO-VISUALIZER-REFINEMENT.md](RADIO-VISUALIZER-REFINEMENT.md) and radio-refinement-verification.json. The original release details below are historical.

Compact equalizer icon in the existing radio transport opens an audio-reactive visualizer. Wave, Spectrum and Orbit modes and three color palettes are remembered. The open visualizer enables sensor rotation and fills the display in landscape, restoring the prior orientation on dismissal. Landscape controls can be hidden/revealed by tapping the picture and hide after five seconds of active playback; Close, system Back and transport remain available when controls are shown. Portrait includes an explicit rotation hint.

Original Compose Canvas implementation inspired by the [Velo visualizer](https://github.com/rorygallagher2024/velo-visualiser), not a port: no Velo source/assets or dependencies incorporated. No smart lighting, system-audio capture, microphone input, HDR or sub-10ms/120fps performance claim. All analysis is local and ephemeral.

The existing Android Visualizer is attached only to the positive, signed-owner-authorized radio MediaPlayer audio session. No session0/global mix. One shared capture feeds the existing miniature waveform and the large visualizer, at up to30 captures/sec and1024sample buffers. Packed FFT uses32 log-spaced40Hz–16kHz bands, excluding DC/Nyquist. Actual sample availability determines motion; silence/paused output has a quiet baseline. Capture is released and cleared on pause, background, preference disable, app exit and session replacement. Polling rechecks the authorized session every500ms while eligible, including station switches that keep the playing state.

Android RECORD_AUDIO permission remains required by Android's output Visualizer API; the microphone is not opened. A declined/disabled permission has an explicit Enable audio visuals action and playback remains usable. Unsupported output capture reports unavailable with Retry; no synthetic beats. Original radio host and publisher/capability identities are retained.

Phone acceptance still needed: actual stream audio/FFT reaction, station switch, Bluetooth/wired/output routing, permission decline/regrant, background/resume, full sensor landscape and return, system bars/cutouts, OLED/battery/performance and screen-reader/large-font layout. Host tests cannot establish handset latency or OEM audio-effect support. Included in OnKlav0.100.9-rc1/code118; package/signature/source consistency and packaged visualizer code verified. See radio-visualizer-apk-verification.json.
