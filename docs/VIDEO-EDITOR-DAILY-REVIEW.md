# Video Editor: everyday editing review

Source review and implementation, 2026-10-30. No new APK requested or built. The latest delivered APK remains 0.100.26-rc1/code135.

## Scope and approach

Reviewed workspace/layout, timeline hit testing and trim mapping, edit/undo boundaries, project persistence/recovery/switching, preview/focus/lifecycle paths, composition/export settings, audio/overlay/title handling, captions, proxies and portable backups. Existing advanced features and single-APK/signed SDK boundaries were retained. Changes target correctness and usability rather than adding a new processing stack. No new native dependency or signing identity was introduced.

## Findings and implemented changes

| Finding | Everyday effect | Result |
| --- | --- | --- |
| Trim dragging multiplied the entire drag by only the speed at the original edge. | A trim crossing a speed curve landed on the wrong source frame; extending a trimmed edge could be inconsistent. | Integrated output/source time mapping across every rate segment, including the untrimmed source. Drag offset is anchored at gesture start. The 100 ms source-span guard and snapping remain. |
| Shortening a clip discarded keyframes after the cut without retaining the motion at the boundary. | An animated zoom/pan could become static or change shape throughout the remaining clip. | Preserve a sampled boundary key and the original easing subinterval. Motion before the cut stays continuous. |
| Slider edits changed revision without marking the edit gesture active. | Automatic preview could prepare a composition while a slider was still held, interrupting editing or temporarily disabling controls. | Draft changes suppress automatic preview until commit/gesture completion. Programmatic completed edits and history operations clear that state. Failed saves also suppress automatic preview. |
| Preview surface had arbitrary panel proportions. | Letterboxing and drag distances could feel different from the project's export canvas, especially for portrait video. | Fit and clip an explicit project-aspect frame inside the available preview area; use the same boundary for gestures, ordinary player and full-screen player. The outer area remains available for layout. |
| Export/Canvas chips called apply for every click, including before Cancel. | Cancelling a settings dialog could still change edits, canvas and undo history. | Dialog-local draft; Cancel discards it. Canvas applies once at Done. Export resolution/frame rate/bitrate are snapshotted separately and do not alter the editing timeline/canvas. |
| Failed autosave could be dismissed; export could proceed without durable edits. | Users could lose track of unsaved work or believe a project was safely stored. | Persistent unsaved state and Retry save action; block export and project switching until commit succeeds. Keep edits in memory and make retry explicit. |
| New/open project publication could precede a failed store write. | A storage problem could replace the visible project with an undurable one. | Store the new/opened project and current pointer before publishing it to the editor. Failure retains the previous active project. |
| Undo during an uncommitted edit could bypass the pending edit. | A value could be lost or undo could behave inconsistently after an interrupted slider gesture. | Commit pending edits first; stop on failure. Redo is unavailable for a new pending branch. Undo/redo finish in a settled preview state. |
| Every ordinary commit reparsed the entire project library and rewrote the same current-project pointer. | Increasing project count added avoidable work to every slider release. | Update the in-memory saved project row directly and avoid redundant pointer writes. Pointer reads still honor AtomicFile recovery. |
| Landscape split layout started only at 600 dp; very short tool views kept a preview and transport that consumed the inspector's space. | Tools were squeezed into a small, awkward viewport. | Start split layout at 480 dp when sufficiently wide; use a shorter timeline on landscape. On short/large-text portrait views, prioritize the inspector and restore preview/timeline at Done. |
| Export choices were horizontal strips with important options off-screen. | Settings were harder to discover and understand. | Full-width labeled selectors, output pixel dimensions, explicit frame-rate limit and quality labels, bitrate-based size estimate when meaningful, and a clear Choose save location action. Actual saved size appears in export completion status. |
| Tapping the text lane did not select the clip at the tapped time; overlay taps did not seek. | Users opened controls for the wrong clip or positioned layers without seeing the tapped moment. | Text taps select and seek; overlay taps seek before opening that layer. Existing selected audio lane behavior is retained. |
| Selected layer/tool context could survive a project switch. | The new project could show stale overlay/inspector context. | Key active tool group, tool and selected layer state by project identity. |
| Photo clips displayed an ineffective clip-volume control. | Users had to infer that the source had no sound. | Show a clear no-audio explanation; keep Add audio/Voiceover available. Real clip audio gains a quick Mute clip switch; unmute restores normal 100% volume. |
| Audio fades could remain longer than a newly trimmed/slowed track. | A short track could stay quiet because its fade never reached normal volume. | Clamp fades to the resulting track duration when its controls change. |
| Timeline ruler/playhead were hard-coded white. | Ruler labels and the playhead could disappear in light themes. | Theme-aware ruler text and a contrasting two-tone playhead; ordinary clip labels remain white on their dark strip. |
| Exact trim used a different numeric parser and did not accommodate the keyboard. | Decimal commas failed, and fields could be awkward to reach. | Use the shared finite/range-checked millisecond parser; add IME-aware scrolling. Photo duration now permits 0.1-second edits instead of imposing a one-second minimum. |
| Portable backup allowed up to 16 GB while the internal Files ZIP limit is 256 MB. | A large backup could fail after writing, with an avoidable recovery artifact. | Check missing media and conservatively estimate archive size before opening a host save. Explain that larger backups require a connected phone folder. Connected provider destinations retain the existing archive limits. |
| An older regression expected missing media to make a project unloadable. | The test contradicted the existing recovery rule and newer refinement tests. | Assert that edits remain loadable and the missing file is reported, preserving the established recovery behavior. |

## Features confirmed and retained

Main video/photo sequence (up to100 clips), split/duplicate/reorder/delete, exact trim and frame stepping, canvas aspect/fill, zoom/pan/rotation/flip, timed text and manual/imported SRT/WebVTT captions, keyframes and easing, stepped speed curves, fades/overlapping transitions, color and cube LUT controls, up to four overlays with cutout/mask controls, up to four imported/recorded sound tracks, extraction, tone/pitch/noise controls, approximate beat markers, narration ducking, preview proxies, project library, portable backups and atomic/recovery project persistence. Undo/redo remain per editing session. Exports use original sources, not proxies. Files pickers/saves and existing SDK grants remain in place.

A fallback thumbnail is labeled as a source frame; it is not an encoded-effects preview. The actual player is still needed to review final motion, color, timing and sound. A real canvas boundary improves positioning without claiming that a still source image reproduces every effect.

## Important limits and future candidates

- Main-thread atomic project JSON writes remain. Avoidable library scans and pointer writes were removed, but a full asynchronous autosave queue needs durable acknowledgements, serialized project switches and explicit exit barriers. It should be a separate measured change rather than silently replacing recovery guarantees.
- Reverse-video processing, linked/ripple edits across tracks, a waveform timeline, range-loop playback, reusable project templates and direct media relinking are useful future candidates. They are not newly implemented or advertised here. Music/overlays currently use absolute timeline placement; moving a main clip does not automatically link or move them. Missing private media is reported and portable-backup restoration remains the recovery path.
- Automatic speech transcription/captions, optical-flow slow motion, stabilization and AI background removal require additional processing models/engines. Current captions are manual or imported, speed changes use existing timing effects, and background cutout is chroma/mask based.
- Real Samsung codec/GPU behavior, A/V synchronization, export quality/bitrate/frame delivery, HEIC/HDR, long projects, keyboard/rotation and screen-off/background behavior require device acceptance. The current lifecycle still cancels long operations when the editor stops, as its guide states. This review does not claim persistent background exports or physical phone performance measurements.
- There is no blanket claim that all defects are eliminated. The source changes and exact host checks are recorded in video-daily-review-verification.json; evidence and reviewed screenshots accompany that file.
