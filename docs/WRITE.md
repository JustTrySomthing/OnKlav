# Write — mobile rich-text word processor (0.93/code101)

Write is a signed included SDK app inside OnKlav, not a separate APK. Its Rust/Wasm shell provides package identity and session lifecycle; the host supplies a native Android EditText rich-text workspace inside the shared SDK chrome. Core/JNI sources are unchanged. This first-party workspace is not yet a public third-party word-processing SDK component.

The theme controls the toolbar, panels and dialogs. A white document canvas shows actual text/highlight colors consistently. Formatting includes bold, italic, underline, strikethrough, text and background colors (palette/custom hex/default), three font families, font sizes, title/headings, links, clear character style, paragraph alignment/indentation, bullets and numbered lists. Native editing retains Android selection, IME, cut/copy/paste and scrollbar behavior. Formatting acts on the selected text or insertion point. Numbered lists are renumbered after edits. Undo/redo stores bounded rich snapshots and groups nearby typing; find/replace supports wraparound and replace all. Word/character counts are visible.

Documents: folder button, New, Import, Rename by title, Duplicate current, confirmed Delete. Autosave after550ms, explicit Save/retry, last-document restoration and atomic private JSON files. Switching/duplicating/importing flushes the current document before changing it. Imports create a new private document and leave source files unchanged. Storage and native clipboard actions check current SDK grants; revocation hides the workspace. Delete-app-data removes the Write folder and current-document preference.

Exports: editable native .write, plain UTF-8 TXT, HTML, basic OOXML DOCX, and paginated A4 PDF. Native Write preserves all supported marks. DOCX supports explicit run formatting, lists, alignment, fonts/sizes, color/highlight and hyperlinks; imports read basic text/inline formatting/list metadata, not all Word style inheritance or layout features. PDF uses the native text layout and document renderer; hyperlinks remain styled text in PDF. HTML import uses Android's inert text/span parser, not a WebView. No scripts, remote resources or network requests are executed.

Limits:500,000characters,50,000formatting marks,8MB native JSON,12MB import bytes,512ZIP items and24MB cumulative DOCX inflation; no ZIP extraction into user directories. Fonts are system sans/serif/monospace. No images/tables, tracked changes, comments, footnotes, collaboration, advanced page layout or legacy binary .doc support. Advanced Word document layouts may differ on import/export. This is an on-device text word processor, not complete Microsoft Word compatibility. Phone keyboard/provider acceptance remains separate.

Validation: Five unique focused Android checks passed:4core and1isolated UI; full lint0errors/192warnings. All18signed included apps current. Native core/JNI unchanged; no APK built. PDF layout/pagination is checked; physical PDF file/provider and keyboard acceptance remain separate. UI checks use bounded ScrollBy with explicit layout/pump; do not use performScrollTo on off-screen controls with the paused root.

DOCX XML writes stream into ZIP and paragraph formatting is indexed locally rather than rescanning the entire mark list per text segment. Native PDF byte output is not supported by this host test runtime; only native layout/pagination and the export-dialog flow were validated here. Current drafts remain visible in Documents before autosave completes, and undo retains a bounded editing position.
