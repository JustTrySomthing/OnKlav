# Included app defaults —0.99.1/code108

YouTube downloads were added with files.manage, but AppSdk.bootstrap upgraded included packages with the intersection of old grants and new capabilities. A device whose first-use defaults were already recorded could never receive the new capability automatically.

Automatic and manually selected included-package upgrades now add newly declared capabilities, retaining prior choices for existing capabilities and excluding removed capabilities. Publisher matching remains required. External app installation is unchanged. A one-time, original-publisher-checked YouTube migration restores storage.private/network.web/clipboard.read/clipboard.write/files.manage for already-installed copies and marks readiness only after success. The embedded web broker also requires both clipboard capabilities; these are included so downloads and the reopened video page actually work. Other previously disabled YouTube capabilities remain disabled. Removed apps stay removed. Later deliberate revocations remain effective.

The download dialog no longer directs users to nonexistent download settings. Normal installs are ready by default. If downloads are deliberately disabled later, Enable downloads is provided inside the dialog; it restores only required declared access and opens a fresh working session, retaining saved YouTube page state. Permission changes invalidate sessions in the core, so the inline repair runs in the model lifetime and reopens after granting. The browser WebView already allows provider playback without requiring an additional user-gesture setting.
