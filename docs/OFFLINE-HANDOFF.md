# Offline podcasts and network handoff —0.100.2/code111

The delivered0.100.1APK contains the initial NAT64/default-route recovery, but physical Wi-Fi/mobile acceptance is not established. User reports all radio/podcast connections failing after leaving Wi-Fi and inability to play a previously downloaded episode.

Opening a podcast’s episode list previously always reloaded its RSS feed after the short memory cache expired; downloaded episodes could therefore become unreachable offline. The host now builds a paged episode list from valid local download metadata when offline, and falls back to it on feed errors. New downloads retain their show title; old downloads use the current saved show title. Play still checks local files before resolving audio URLs. Downloaded playback now passes a checked read-only file descriptor directly to MediaPlayer rather than sending local reads through a custom decoder callback. Live app ownership, authorization, pause/stop and revocation remain enforced. No RSS, DNS or HTTP is required by the local-file path.

For handoff, queued callbacks from a lost or superseded default route are discarded. Newly validated routes clear radio/podcast/media idle connection pools, rebuild the remote source, retain podcast position and leave local playback alone. Standard safe GET connection fallback is enabled for stale connections and dual-stack IP alternatives. A failed handoff gets one delayed attempt for that route; repeated failure stops retrying. Pause, Stop, replacement, authorization loss and shutdown prevent restart. Pending seek targets survive a source rebuild and are retained until the decoder completes seeking, avoiding a handoff race that reset playback position.
