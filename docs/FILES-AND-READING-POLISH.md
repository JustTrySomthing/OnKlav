# Default file UI, Convert and eBook polish

All ordinary file open/multi-open/create/save actions in host modules and shared Settings use OnKlavFileContracts. Existing FileExportContract delegates to the same explicit internal Activity. SDK blobs.import/export, library.import/export, images.import and file-backed native editors therefore use OnKlav Files without guest changes or new capabilities. SDK libraries continue to return opaque IDs; native URIs/paths never become a guest interface.

The selection surface adapts the existing signed Files controller and its Rust content broker, using the same OnKlav folders and connected Android locations. Search, paging, folders, filtered files, multiple selection, cancel, new folder and Save As are supported. Save As never overwrites existing shared content: the broker chooses a unique name. Open selections receive non-exported, unguessable host URI tokens; writes use durable private staging and the existing authorized Rust import at descriptor close, recording the real size. Filing failures preserve the raw write and show Recovered saves, also reachable from Files Home with explicit retry. Active writes are excluded from recovery. No shared-index JSON is read/rewritten by Kotlin. Interrupted exports can be partial; review recovered files before using them. Storage/permission failures remain visible.

Android’s system tree grant is used only after an explicit Connect phone folder action (in Files or the picker), because Android owns that permission. All subsequent browsing is inside OnKlav. There is no broad-storage permission. Provider folder imports for AudioBooks accept the same internal folder selection. Existing contacts/calendar/system approval flows and camera capture intents remain distinct from ordinary file selection.

Convert uses modern measurement/unit selectors, two clearly labeled value cards, compact swap/copy and inline validation. The existing signed Rust controller still owns every calculation, unit, fraction/feet-inch conversion and preference. eBooks has a readable line-height and a grouped footer that selects Next page or Next chapter according to actual controller availability, explains transitions and ends with Book complete. Previous page/chapter, Contents, bookmarks, position recovery and native one-row Read Aloud controls remain available. Signed guest code, publisher and core/JNI are unchanged.
