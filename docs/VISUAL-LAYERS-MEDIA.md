# Visualizer, editable image projects and local media

Source update after 0.100.16-rc1/code125. No new APK has been requested for this change.

Radio uses neutral medium/light gray transport, intensity and heading controls. Rainbow is the default seventh color option when no explicit color has been saved; selected single-color families remain available. Each scene has its own starting strength, and selecting another effect resets the slider to that scene's default. The Wave ribbon supports a multicolor gradient. Mandala contours rotate at independent alternating rates, with separate bass/mid/upper-mid/treble envelopes and stronger radius/lobe travel. Beads remain attached. Spectrum pairs follow their own interpolated FFT band instead of sharing the maximum bass envelope, retain the mirrored central silhouette and use wider bars with varied saturation/value. Gain leaves room for variation at normal intensity rather than flattening the center at the cap.

Image text commits when switching tools or tabs, as well as on Check/Done/Save. Invalid labels remain inline for correction. Committing dismisses the keyboard. Save a copy offers JPEG, PNG and Layers; the save dialog scrolls on smaller windows. `.layers` is a versioned ZIP project containing the unmodified original bytes, editable adjustments/marks, and bounded Undo/Redo history. Open it from Image Editor's folder button. The original source stays separate from adjustments, so crop/geometry/text remain reversible; this is not a flattened PNG disguised as a project. Working history also restores after reopening the app. Project opening validates before replacing the current source, uses the existing crash-recovery journal and does not save a flattened image over the Layers file. Unknown versions, unexpected archive entries and excess uncompressed/history sizes are rejected. No arbitrary archive paths are extracted.

The Android location in Files and the shared built-in picker offers Images, Videos, Audio, Downloads, Documents, Camera and Files shortcuts. Already-connected standard folders open directly. Otherwise a location hint opens Android's one-time folder grant; subsequent browsing and file operations remain in OnKlav. Android may require a subfolder under Downloads or storage root. This does not bypass OS folder restrictions, grant broad storage permission, or claim automatic access to every provider's entire media library. Existing signed Files capabilities, live grants and tokens remain authoritative.

Video soundtracks now declare an audio-only sequence, including audio-only gaps, and pad the end to the project duration. An imported M4A must not introduce a phantom video input or shorten the mixed timeline. Existing MP3 normalization remains. Exact screenshot/device codec failure is not reproduced on a handset; real M4A/AAC playback, GPU preview and export remain device acceptance work.

Audio-only YouTube downloads decode locally and encode a real 192 kbps MP3 using the existing bundled shared encoder. Display label, filename and MIME are MP3/audio/mpeg; video downloads retain their existing path. Download authorization/link rules, size/storage/cancellation limits and no-DRM-bypass behavior remain. Source audio uses available local Android decoders (or the existing MP3 software decoder); protected/unsupported media still reports an error. No cloud/AI service or new dependency is added.

Validation evidence is under `docs/evidence/visual-layers-media/` and `docs/visual-layers-media-verification.json`. Initial workflow diagnostics are retained, including the too-early canvas assertion and truncated 105% label that were corrected. No broad unaffected suite or APK assembly is required for this source task. Physical phone stream/route, folder/provider, IME/touch, codec/GPU and process/storage acceptance remain separate.
