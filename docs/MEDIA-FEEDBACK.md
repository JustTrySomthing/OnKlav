# Podcast feedback and radio health — 0.86 source update

Episode rows in Show and Recent now display measured download progress under the row: a determinate bar, percentage and bytes/total when the publisher supplies a length, or an indeterminate bar with received bytes for unknown lengths. Connecting, Download complete, Unable to download with a useful reason, and cancellation are explicit. Cancel is available beside progress as well as in the host request area. Completed downloads continue to be played locally. No completion is reported until audio and metadata are committed; failed staging files are removed.

The download uses the existing scoped, private, bounded disk transfer and checks live authorization while reading. Progress updates are throttled by time/bytes and do not run guest effects or rebuild the app's state on every chunk. Published totals and byte counts reflect bytes actually written. The same publisher and2GiB/500download limits remain. Requests remain foreground; leaving Podcasts cancels unfinished work, while completed files survive reopening.

Podcast compatibility fixes include safe public TLS ports for audio, correct HTTP-to-HTTPS upgrade of explicit port80 URLs, and additional valid enclosure MIME aliases. Public HTTPS and address/redirect validation remain enforced. The resolver can use a small range probe instead of starting a second whole-body transfer. Existing no-account/non-subscription playback remains unchanged.

A server that ignores byte-range requests no longer hits the previous16MiB tail-seek/256MiB discard barriers. Podcasts use one bounded disk-backed sequential response for that fallback; seeking back reuses cached bytes. Servers that deliver a file in bounded206segments are continued instead of mistaking the end of a segment for the end of the episode. Matching length/validator checks still reject changed media rather than joining incompatible audio versions. Podcast preparation permits a longer bounded wait for a server requiring sequential tail metadata, and player failures give useful format/connection/retry guidance; decoder codes are kept in internal logs. Unsupported, removed, restricted or broken publisher files cannot be guaranteed to play.

Radio Browser's hidebroken projection remains in place. Confirmed HTTP403/404/410, non-audio stream responses, or decoder malformed/unsupported errors mark a station unavailable for24hours, including known aliases. Stations disappear immediately from Stations and are excluded from new browse/search snapshots. Existing page snapshots retain cursor positions; favorites/recent data are kept. Radio settings offers Retry unavailable stations. Permission loss, unknown decoder failures and a general connection outage do not blacklist stations. This does not claim to have actively probed every station; doing so would make browsing slow and burden broadcasters.

Validation and remaining device/provider limits are recorded in media-feedback-verification.json. The two named podcast feeds (History That Doesn't Suck; Stuff You Missed in History Class) returned parseable episode lists and actual audio bytes with206responses during the public-source check; that is not Android decoder/phone acceptance.
