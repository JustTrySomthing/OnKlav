## Playback / lifecycle

The separate core/speech JNI library keeps neural dependencies out of each Wasm app. One worker/model serializes synthesis; short text (including the approved reference) is preserved intact. Long text is split on natural boundaries into at most220UTF-16-unit pieces, without custom phoneme rewriting. Synthesized PCM stays in RAM. The producer generates ahead while a native AAudio callback consumes a preallocated10-second single-producer/single-consumer ring. The callback does not allocate, lock, enter JNI or do disk/network work. Actual output rate/format/channels are checked. Endpoint frame/timestamp draining prevents closing while final words are still queued for the hardware. Stalled/disconnected output reports a retryable error.

Stop cancels/invalidates the run and silences queued audio. One in-flight synthesis call may finish, but its stale samples/callbacks are discarded. Open/close driver operations are outside the UI handle lock; only short handle/cancel/query operations synchronize. Playback and pending word-position markers stay bounded, rather than accumulating a book's history. All clients retain common HostSpeechOwner/audio-focus handoff and capability/session/widget rechecks. Moving to another audio owner stops the previous reader. Genuine low-memory trimming unloads an idle model safely through the worker; UI_HIDDEN alone keeps the model warm.

Built-in Read Aloud/eBooks use a user-started, nonexported foreground media service with private notification, play/pause/stop, headset/Bluetooth noisy-route pause and a non-reference-counted bounded renewed wake lock. The foreground lease is attached while an explicit request is still preparing, so locking during cold initialization does not cancel it; preparing also holds the bounded wake lock. Paused sessions keep notification controls when the UI stops. Screen-off retains an authorized built-in reading session; navigation/disposal, revocation and service destruction clean it up. Paused reading retains an ownership cleanup hook so starting Radio/another player dismisses the old paused session. Five minutes paused releases the service. SDK apps otherwise remain foreground-scoped; speech.output does not silently grant arbitrary background access. eBook page completion uses a once-per-run callback and a live frame collector that can receive the next page while the UI is stopped, with duplicate-frame protection.

Word-position feedback is estimated from played PCM and text weights, not native word timestamps or forced alignment; this is disclosed in speech settings/SDK docs. Page transitions can still require the next SDK page to load. No claim of zero latency, within-sentence streaming or measured Samsung/Bluetooth endurance is made.

## Build / packaging

core/speech/Cargo.toml pins official sherpa-onnx1.13.8/shared. scripts/build_speech.py --host builds/checks Rust host and Android ARM64 JNI, verifies16KiB alignment and writes a separate source/outputs proof. Main scripts/build.py has its own neural_speech reuse/build stage; host checks reject stale speech artifacts. APK verification checks required JNI/service classes, all three exact native libraries and the exact voice pack/manifest. JNI names are kept under optimization. Runtime/model/dependency bytes are pinned and verified; mismatched versions cannot silently be recertified. Only original speakers0/2 and English pronunciation files are included. scripts/build_compact_speech.py verifies pinned inputs, preserves the FP32 graph/style rows/selected speed priors, and changes metadata to index compact rows0/1. It does not substitute INT8/Mini models. The manifest pins the derived pack separately from its original upstream archive. No new Android runtime permission is required: existing foreground-media/wake/notification setup is used.
