# Signed .onklav-g / godot.web.v1

A ZIP contains manifest.json, publisher.json, signature.bin and web/index.html, web/index.pck plus exported web content. It never contains the shared files listed in engine.json. Names are bounded relative ASCII paths, with no empty/dot/dot-dot components, backslashes, duplicate names or directories. No extraction into arbitrary filesystem locations occurs at runtime. The host verifies all contents before committing an installation and verifies again before opening an immutable archive handle.

Manifest schema onklav.package.v1, kind game, runtime godot.web.v1, engine4.7.2, entry web/index.html, reverse-domain lowercase id, name/version/description, positive integer version_code, profile arcade/turn_based, orientation portrait/landscape/sensor, empty permissions and the exact engine_assets SHA256 inventory (including onklav-controls.json), controls="onklav.game.controls.v2", and integer min_host=166 for SDK0.6.1 entry and saves (older controls packages remain readable). Future permissions require a separately implemented broker and user consent; arbitrary Android permissions are never accepted.

publisher.json contains algorithm ECDSA-P256-SHA256, a lowercase hex DER SubjectPublicKeyInfo public_key (secp256r1,91 bytes), and files_sha256 mapping every content name (including manifest.json) to its lowercase SHA256. signature.bin is a DER ECDSA signature over the exact bytes `onklav.game.signature.v1` + one NUL byte + raw publisher.json. The host validates curve, signature and exact content inventory, not a reserialized approximation. Publisher fingerprint is SHA256 of the public DER bytes. The developer private key is a32-byte P256 scalar and is never included in packages.

Signing establishes update identity. It neither requires owner approval nor guarantees safe game behavior. Verification is separate from sandboxing and user confirmation. The exact ZIP SHA256 identifies an installed package; same-version different bytes are refused. A newer version must have a greater version_code and the same publisher. Existing identities survive removal to prevent unnoticed publisher replacement/rollback.

The package's custom HTML is untrusted code and subject to the same origin, content-security and request interception policies as its GDScript/WebAssembly. It cannot select a different engine URL, follow an external URL, open host files or receive an Android bridge. Web resource paths are never interpreted as arbitrary host filesystem paths.

See [GAME-CONTROLS.md](GAME-CONTROLS.md) for required interaction semantics and supported-mode callbacks. These controls originated in host157; acknowledged per-game saves originated in host165 and preflight entry requires host166; older fingerprints/controls are not interchangeable.

The signed play_modes must be exactly ["single"] or ["single","turn_sms"]. The second requires profile turn_based. Missing modes in older metadata default to single for validation; older engine/control fingerprints still require an explicit SDK upgrade. turn_sms grants no arbitrary SMS permission to game code: the native host limits turns to an explicitly accepted match with the same installed game package. See SMS-TURNS.md.
